# Задание: правки от 2026-07-12

Действуем по той же схеме: по порядку, тестируя каждую. Часть пунктов зависит от внешних
сервисов/секретов — они помечены (DECISION) и уточняются у пользователя до реализации.

Порядок реализации (по зависимостям и риску):
4 (English) → 3 (модалка) + 6 (карандаш) → 2 (пользователи/сессии) →
5 (PDF+почта) → 7 (фото из интернета) → 1 (живой сканер с маской).

## 4. Весь интерфейс на английском
Все видимые строки — на английском. В частности «в зале X из Y» → «in hall X / Y»,
тексты модалок, подписи. Проверка: по всему `app/` не осталось кириллицы в UI.

## 3. Модалка подтверждения «Finish»
Кнопка «Finish replenishment» открывает модалку подтверждения (вместо `window.confirm`):
заголовок, вопрос, «Cancel» / «Finish». Внутри — чекбокс из п.5.
Проверка: клик по Finish показывает модалку; Cancel закрывает без действий; Finish завершает.

## 6. Кнопка-карандаш для редактирования
В списках у товара — иконка-карандаш; по нажатию открывается редактирование и иконка
меняется на «закрыть» (×). Повторное нажатие/крестик закрывает панель.
Проверка: карандаш ↔ крестик, панель раскрывается/сворачивается.

## 2. Пользователи (имя + пароль) и хранение сессий (DECISION: модель регистрации)
- Prisma: `User { id, username @unique, passwordHash, createdAt }`;
  `ReplenishmentRequest.userId` → связь сессий с пользователем.
- Пароли хешируются (scrypt из `node:crypto`, соль в хеше) — без нативных зависимостей на
  serverless. Пароли не логируются и не коммитятся.
- Логин: `POST /api/auth/login` проверяет пароль, ставит подписанную httpOnly-cookie
  (HMAC, секрет `SESSION_SECRET`), stateless. `POST /api/auth/logout` чистит cookie.
- Гейт: без валидной сессии показывается экран входа; после входа — приложение.
- «Все сессии» = прошлые `ReplenishmentRequest` пользователя, доступны для просмотра.
- DECISION → **саморегистрация**: открытый экран входа с переключателем Sign in / Sign up,
  любой заводит username + пароль сам. `POST /api/auth/register`.
- Проверка (curl): регистрация/логин → cookie; запрос без cookie → 401; сессии привязаны к user.

## 5. PDF-отчёт на почту при завершении (DECISION: почтовый сервис)
- В модалке завершения — чекбокс «Send report». Если включён — при Finish
  `POST /api/requests/[id]/report`: собирает PDF и шлёт на **star00@list.ru**.
- PDF: `pdf-lib` (чистый JS, работает на Vercel). Содержимое: дата, пользователь, список по
  отделам (артикул, цвет, сезон, present/need, статус taken/absent), итоги.
- DECISION → **решаем позже**: делаем генерацию PDF и провайдер-интерфейс отправки сейчас;
  реальная отправка выключена, пока не выбран сервис. Если провайдер не сконфигурирован —
  эндпоинт отдаёт PDF на скачивание (или сообщает, что почта не настроена).
- Проверка: завершение с галочкой → 200, письмо с PDF доставлено; без галочки — не шлётся.

## 7. Миниатюра фото вещи из интернета (DECISION: источник картинок)
- Запрос = `${article}${color}` без пробела. Находим картинку, сохраняем URL в
  `RequestItem.imageUrl` (новая колонка). В списках — миниатюра; клик → полный размер
  (переиспользуем существующий просмотрщик фото).
- Поиск на сервере (в `POST /api/scan`, без CORS), URL кешируется на товаре.
- DECISION → **сайт COS** (cosstores.com / cos.com): артикул+цвет — это код товара COS.
  Достаём изображение товара с сайта COS (og:image страницы товара / их изображенческий CDN
  по коду). Точный механизм URL определить при реализации (WebFetch по паттернам COS).
- Проверка: у добавленного товара появляется миниатюра, клик открывает полноразмер.

## 1. Живой сканер с маской (как в банковском приложении)
- Компонент `LiveScanner`: `getUserMedia({ video: { facingMode: 'environment' } })`,
  полноэкранный оверлей с «окном»-маской (рамка/уголки), куда наводится строка кода.
- Периодически (каждые ~350–450 мс) берём кадр, OCR только по области маски (быстро).
- При распознавании валидного кода (17 цифр / артикул): стоп-стрим, `navigator.vibrate(100)`,
  закрыть камеру, заполнить поля (переиспользуем `readLabelCandidates` + парсер).
- Fallback: «Scan from gallery» и «Type manually» остаются (в Telegram-webview доступ к
  видео может быть закрыт — тогда работает съёмка/галерея).
- Проверка (на устройстве): наводка на код → авто-закрытие + вибрация + заполненные поля.
