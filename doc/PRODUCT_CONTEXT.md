# Product Context

## Что мы делаем

Мы делаем Telegram miniapp для пополнения магазина. Сотрудник в торговом зале фотографирует этикетку товара, отмечает размеры, которые уже есть в зале, а приложение формирует список того, что нужно забрать со склада.

Проект называется `store-replenishment`.

## Пользовательский сценарий

1. Сотрудник в зале открывает miniapp на телефоне.
2. Делает фото этикетки товара.
3. OCR на клиенте читает длинный код над баркодом.
4. Приложение извлекает из кода:
   - `article` - первые 7 цифр;
   - `color` - следующие 3 цифры;
   - следующие 2 цифры игнорируются;
   - `season` - следующая 1 цифра;
   - `storage` - последние 4 цифры.
5. Сотрудник может поправить распознанные поля вручную.
6. До, во время или после сканирования сотрудник выбирает размеры, которые уже есть в зале: `XS`, `S`, `M`, `L`, `XL`.
7. Один размер можно выбрать несколько раз.
8. Выбранные размеры показываются под плитками; нажатие на выбранный размер удаляет одну штуку.
9. `Suggested sizes` показывает размеры, которые нужно добавить, исходя из правила: в зале должен быть набор `XS S M L XL`.
10. После `Add to list` товар попадает в краткий складской список.
11. В `Warehouse mode` склад видит товары по отделам, в порядке обхода склада, с нужными размерами и справочной информацией.

## Текущее продуктовое правило по размерам

Для зала обязательный набор:

```text
XS S M L XL
```

`Suggested sizes` - это отсутствующие размеры из этого набора.

Примеры:

```text
present: -
suggested: XS S M L XL

present: XS
suggested: S M L XL

present: XS M M
suggested: S L XL
```

Количество больше одного в `present` не меняет целевой набор: если размер уже есть хотя бы один раз, он не предлагается.

## Код этикетки

Целевой код - 17 цифр над баркодом. OCR может вернуть код слитно или с пробелами.

Пример:

```text
48291011234567890
4829101 123 45 6 7890
```

Разбор:

```text
4829101 123 45 6 7890
article color skip season storage
```

Старый короткий формат вроде `48291 123 2 0101` не является целевым форматом.

## Основные экраны

### Hall mode

Порядок блоков:

1. `Label scanner`
2. `Last parsed code`
3. `Choose existing sizes`
4. `Suggested sizes`
5. `Add to list`
6. `Go to warehouse`
7. `Warehouse short list`

Важно:

- Не возвращать OCR preview.
- Не возвращать scanned article dropdown.
- Размеры `XS S M L XL` должны быть доступны до завершения OCR.
- Поля `Last parsed code` должны быть редактируемыми.

### Warehouse mode

Warehouse mode должен показывать:

- группировку по отделам склада;
- сортировку внутри отдела по `article`, затем `season`, затем `color`;
- `article`;
- `color`;
- `season`;
- `needed sizes`;
- справочно `present sizes`;
- переход к фото скана по клику на `article`, если фото сохранено;
- понятную обработку отсутствия фото.

## Текущий технический стек

- Next.js 16 App Router
- React 19
- Prisma 6
- SQLite
- Tesseract.js на клиенте
- Tailwind CSS 4

## Главные файлы

- `app/page.tsx` - основной экран и клиентская логика.
- `app/api/label/extract/route.ts` - API для извлечения кода из OCR-текста.
- `lib/label-extractor.ts` - парсер этикетки.
- `app/api/scan/route.ts` - создание элемента заявки и расчет suggested sizes.
- `app/api/requests/[id]/warehouse/route.ts` - складское представление.
- `lib/replenishment.ts` - правила расчета размеров.
- `prisma/schema.prisma` - модель данных.
- `lib/prisma.ts` - Prisma Client singleton.
