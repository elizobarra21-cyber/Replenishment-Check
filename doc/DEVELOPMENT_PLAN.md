# Development Plan

Документ фиксирует фазы разработки и критерии успеха. Его нужно обновлять, если продуктовый план меняется.

## Фаза 0 - База проекта

Статус: выполнено.

Цель: поднять Next.js + Prisma + SQLite проект с seed-данными и базовыми API.

Критерии успеха:

- `npm run build` проходит без ошибок.
- Prisma schema содержит каталог товаров, секции склада, заявки и элементы заявки.
- Есть seed-данные для локальной проверки.
- API умеет создавать заявку.

Ключевые файлы:

- `prisma/schema.prisma`
- `prisma/seed.ts`
- `app/api/requests/route.ts`
- `app/api/bootstrap/route.ts`

## Фаза 1 - Hall scan MVP

Статус: в работе, основа реализована.

Цель: сотрудник в зале может сканировать этикетку, редактировать распознанные поля, выбирать размеры в зале и добавлять товар в список.

Критерии успеха:

- `Label scanner` запускает OCR через `tesseract.js`.
- Парсер принимает 17-значный код слитно и по пробелам.
- `Last parsed code` отображает код с пробелами.
- Поля `article`, `color`, `season`, `storage` редактируемые.
- Плитки `XS S M L XL` доступны до завершения OCR.
- Один размер можно выбрать несколько раз.
- Выбранные размеры отображаются под плитками.
- Нажатие на выбранный размер удаляет одну штуку.
- `Suggested sizes` показывает отсутствующие размеры из `XS S M L XL`.
- `Add to list` сохраняет элемент заявки.

Оставшиеся риски:

- OCR на реальных этикетках может ошибаться по строке над баркодом.
- Фото скана сейчас сохраняется как data URL, что подходит для локального MVP, но не для production-хранилища.

## Фаза 2 - Warehouse picking MVP

Статус: основа реализована.

Цель: склад получает удобный список товаров для пополнения.

Критерии успеха:

- Есть `Warehouse mode`.
- Товары сгруппированы по отделам.
- Отделы отсортированы по `warehouseOrder`.
- Внутри отдела сортировка: `article`, `season`, `color`.
- Карточка товара показывает:
  - `article`;
  - `color`;
  - `season`;
  - `needed sizes`;
  - `present sizes`;
  - название товара;
  - storage section.
- Клик по `article` открывает фото скана, если оно есть.
- Отсутствие фото обрабатывается текстовым сообщением.

## Фаза 3 - Реальная Telegram miniapp интеграция

Статус: не начато.

Цель: запустить приложение как Telegram miniapp, а не только как локальный мобильный веб.

Критерии успеха:

- Приложение доступно по публичному HTTPS URL.
- Miniapp открывается из Telegram.
- Камера/галерея работают на целевых телефонах.
- Есть понятный способ идентифицировать сотрудника.
- Поток `scan -> choose sizes -> add -> warehouse` работает внутри Telegram.

Решения, которые нужно принять:

- Где хостить приложение.
- Как хранить фото сканов.
- Нужна ли авторизация через Telegram init data.
- Нужно ли хранить историю заявок между сменами.
