# Задание: правки от 2026-06-29

Реализовывать по порядку, тестируя каждую. Порядок реализации ради эффективности:
1 → 3 → 2 (быстрые), затем 4 (рефактор размерной модели), затем 5.

## 1. Сброс данных товара при новом фото
Когда делается новое фото/скан, а текущий товар ещё не добавлен в список, должна стираться
вся ранее введённая по этому товару информация: имеющиеся размеры (`presentSizesQty`),
визуальный цвет (`colorValue`), поля кода (`lastParsed`), фронт, комментарий, размерная система.

- Место: `handleScanLabel` — в начале (или при старте нового скана) сбросить эти состояния.
- Критерий: набрал размеры/цвет для одного товара, не добавил, сделал новое фото → всё чисто.

## 2. Более явное разделение по отделам (склад и short list)
Заголовки групп-отделов должны быть заметнее: крупнее/контрастнее, с чёткой визуальной
границей между отделами.

- Место: заголовки `Department {n}` и обёртки групп в Warehouse mode и в Hall short list.
- Критерий: отделы визуально явно разделены, заголовок отдела бросается в глаза.

## 3. Единый порядок в списках
Во всех списках: группировать по департаменту (storageSection), внутри — сортировать по
**сезону**, затем по **артикулу**, затем по **цвету**.

- Место: `compareRequestItems` (клиент) и сортировка в `app/api/requests/[id]/warehouse/route.ts`.
- Сейчас порядок: article → season → color. Поменять на: season → article → color
  (группировка по департаменту сохраняется).
- Критерий: в обоих режимах товары идут по сезону, потом артикулу, потом цвету.

## 4. Мужские размерные сетки (по департаменту, начинается на «45»)
Если `storageSection` начинается с **45** — товар мужской, иначе женский. Категория (буквы /
джинсы / числовые) по-прежнему определяется по строке `EUR`.

Каждая (пол × категория) сетка = обязательные (mandatory, входят в target/Y) + опциональные
(optional, выбираемы, но не в target; на складе показываются как `?`). Y = число mandatory.

| Пол | Категория | Mandatory (Y) | Optional |
|---|---|---|---|
| Жен | letter | XS S M L XL (5) | — |
| Жен | jeans (small) | 25 26 27 28 29 30 31 (7) | 24, 32 |
| Жен | numeric (large) | 34 36 38 40 42 (5) | 44 |
| **Муж** | letter | **S M L XL (4)** | **XS** |
| **Муж** | jeans | **29 30 31 32 33 (5)** | **28, 34** |
| **Муж** | numeric | **46 48 50 52 (4)** | **44, 54** |

Определение категории по числу EUR (после определения пола по департаменту):
- жен: 24..32 → jeans, 34..44 → numeric;
- муж: 28..34 → jeans, 44..54 → numeric;
- буквы → letter.

Реализация:
- Расширить `sizeSystem` до 6 значений (жен: `letter`/`small`/`large` — как есть; муж:
  `men-letter`/`men-small`/`men-large`). Старые данные — женские, совместимы.
- `lib/replenishment`: конфиги mandatory/optional на систему; `buildTargetSizes` от mandatory
  (фронты дублируют mandatory до вместимости); `selectableSizesFor` = mandatory + optional;
  optional-сайзы обобщить (п.4 из прошлого пакета — сейчас только 44 у жен-large).
- `detectSizeSystem` (ocr): возвращать не готовую систему, а тип токена (буквы / число+значение);
  финальную систему выбирает клиент по `storageSection` (пол) + числу (категория).
- Опциональные `?`-плашки на складе — по optional-набору системы (обобщить `showOptional44`).
- Критерий: департамент 45xx + EUR 50 → men-large (46,48,50,52 обяз., 44/54 опц., Y=4);
  департамент не 45 + EUR 38 → жен-large (как раньше).

## 5. Ручная смена размерной сетки при создании
В карточке ввода (и в форме редактирования, п.1 прошлого пакета) — контрол выбора размерной
сетки вручную (переопределяет автоопределение).

- UI: выбор пола (муж/жен, по умолчанию из департамента) + категории (letter/jeans/numeric),
  либо компактный список из доступных систем. При смене — пересчитать selectable/target/Y.
- Критерий: можно вручную переключить сетку, «Choose existing sizes» и «X из Y» обновляются.
